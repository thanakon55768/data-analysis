# Phase 3 — ใช้งานแชต Gemini

อัปโหลดไฟล์ เลือกชีตให้พร้อม แล้วใช้ส่วนถามข้อมูลด้วย AI ยืนยันการส่งคำถาม ชื่อ/ชนิดคอลัมน์ และบริบทคำถามล่าสุดไป Google Gemini ก่อนส่ง ระบบส่ง schema และคำถามเพื่อเลือกแผนวิเคราะห์ ส่วน Python คำนวณจากข้อมูลทั้งหมดในเครื่อง Backend และสร้างคำตอบพร้อมหลักฐาน

เครื่องมือที่รองรับ
- ภาพรวม จำนวนแถว คอลัมน์ ค่าว่าง และข้อมูลซ้ำ
- สถิติรายคอลัมน์ตัวเลข
- ผลรวม ค่าเฉลี่ย มัธยฐาน ต่ำสุด สูงสุด และจำนวนแถวแยกตามกลุ่ม

กลุ่มค่าว่างรวมในการคำนวณด้วย ผลรวมของกลุ่มที่ไม่มีตัวเลขเป็น null จำกัด 200 กลุ่มต่อผลลัพธ์และขนาดหลักฐาน 100 KB คำถามที่ยังไม่ชัดเจนจะขอรายละเอียดเพิ่มเติม

บทสนทนาบันทึกใน metadata ของชุดข้อมูล โดยใช้ ownership และ version checks เดิม เก็บสูงสุด 20 คำถามภายใน 200 KB การเปลี่ยนชีตแยกบริบทตามชีต การลบ dataset ลบประวัติไปด้วย ผลลัพธ์ทางตัวเลขใช้ข้อความที่สร้างจากผล Python เพื่อให้ตรวจสอบย้อนกลับได้

## ตั้งค่าใน PowerShell ก่อนเปิด Backend
ตั้ง GEMINI_API_KEY เป็น key ของคุณ และ GEMINI_MODEL เป็นชื่อโมเดลในบัญชี Google AI Studio ที่รองรับ generateContent และ structured JSON output แล้ว restart Backend ตัวแปรเหล่านี้ต้องอยู่ฝั่ง server เท่านั้น หลีกเลี่ยงการนำ key ไปใส่ NEXT_PUBLIC_ หรือ Git

ตัวอย่างชื่อ environment มีใน backend/.env.example โปรแกรม uvicorn รับ environment จาก shell โดยตรง การแก้ไฟล์ .env อย่างเดียวจะยังไม่เปลี่ยนค่าของ process ที่กำลังรัน

เอกสารอ้างอิง API ของ Google
https://ai.google.dev/gemini-api/docs/structured-output

## สถานะการตรวจ
ผู้ใช้เลือกเตรียมโค้ดก่อนมี API key จึงยังไม่ได้เรียก Gemini จริง ทดสอบ model response แบบจำลองเพื่อเช็ก validation, schema-only payload, consent, computed evidence, history persistence และ unknown-column/code rejection แล้ว

ข้อจำกัดปัจจุบัน
คำถามเกี่ยวกับตัวกรองเฉพาะช่วงเวลา การพยากรณ์ กราฟ และ outliers อยู่ในงานถัดไป การเปลี่ยนโครงสร้างคำถามเพื่อรองรับเครื่องมือเพิ่มต้องเพิ่ม validation และ regression checks ไปพร้อมกัน

## ผลตรวจเพิ่มเติม 21 พฤศจิกายน 2026
เชื่อม Gemini ด้วย key ใน environment ฝั่ง Backend แล้ว ทดสอบเรียกโมเดลจริง gemini-3.5-flash-lite เลือกคอลัมน์และคำนวณข้อมูลตัวอย่างได้ผลรวม 30 โมเดล 2.5-flash แจ้งว่าไม่เปิดให้ผู้ใช้ใหม่ และ 3.8-flash ตอบ busy ระหว่างตรวจ จึงเลือกโมเดลที่เรียกสำเร็จ ข้อมูล key ไม่บันทึกใน Git

ปรับ UI เป็น sidebar ไฟล์ พื้นที่บทสนทนา composer ด้านล่าง และแท็บตาราง/สถิติ ตรวจการสลับแท็บ เมนูมือถือ ความกว้าง 390px และ Shift+Enter แล้ว ผลทดสอบ browser E2E เดิมก่อนปรับ UI ไม่ถือเป็นผลรับรอง layout ใหม่นี้
